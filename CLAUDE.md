## Model ↔ disk workflow (hard-won — follow exactly)

- Desktop keeps the model in memory; MCP edits the live model; a Desktop save rewrites
  BOTH the TMDL and the PBIR files from memory. The Desktop CLI cannot save.
- **After every MCP model change:** `database_operations ExportToTmdlFolder` (scratch dir)
  → `bash _build/sync-model.sh <exportDir>` (copies over the project's model files,
  keeps `database.tmdl`) → if HTML radii were touched, `node _build/radius-model.js`.
- **To load disk model changes into Desktop:** the user clicks **Apply** on Desktop's
  "external changes" alert, or closes Desktop WITHOUT saving and reopens.
  `powerbi-desktop reload` reloads the REPORT only, never the model.
- **Never create M-partition tables via MCP** (Desktop doesn't register them, so a save
  drops them). Create those by editing TMDL with Desktop closed. MCP is fine for
  measures, DAX calculated tables, relationships, column properties and partition updates.
- For bulk mechanical model edits (recolour, radius) a script over `_Measures.tmdl` +
  user "Apply" is more reliable than retyping many long measures through MCP.
- Before reloading the report, `powerbi-desktop status` may show `hasUnsavedChanges: true`
  from MCP edits; that is expected once the model is synced to disk.

## Build tooling (`_build/`)

- `node gen.js` — wipes and rewrites every page, nav/filter bookmarks and icon resources.
  Deterministic IDs (sha1 of keys) → idempotent. Page builders in `pages/<key>.js`,
  helpers in `lib.js` (encoders, `cardVCO`, `bareVCO`), icons in `icons.js`.
- Test switches: `KIVA_MODE=Dark`, `KIVA_DRAWER_OPEN=1`, `KIVA_FILTERS_OPEN=1`
  (always re-run plain `node gen.js` afterwards).
- `node write-theme.js` — writes the theme with a fresh suffix and re-registers it
  (run it BEFORE `gen.js`, which re-adds the icon resources).
- `bash sync-model.sh <exportDir>` — MCP export → project model files.
- `recolor-model.js`, `recolor-report.js`, `radius-model.js` — idempotent restyle scripts.
- Loop: edit → `node gen.js` → `powerbi-report-author validate "<.Report dir>"` →
  `powerbi-desktop reload --pid <pid>` (retry once if it returns "error") → screenshot
  (throwaway first, HTML visuals animate in) → review.

## PBIR gotchas confirmed (don't rediscover)

- actionButton / navigators need the **dual-entry** pattern (static entry + `id:'default'`)
  or fill/text overrides are silently dropped; `fill.show:false` is ignored → use
  `show:true` + `transparency:100`. Same for shape fill.
- Shape text doesn't render → use action-less buttons as labels. Button text can be
  measure-bound (`text: { expr: Measure }`).
- advancedSlicerVisual: tile colour comes from `fillCustom` (set show:false); state
  selectors on background look ineffective; on a field parameter it blanks the selected
  tile's text and a Label measure errors → use a classic slicer (Basic + orientation 1).
- Treemap `FillRule` is ignored → per-category `dataPoint.fill` with `scopeId`
  Comparison selectors. decompositionTree props are prefixed (`positiveBarColor`,
  `categoryLabelFontColor`, `levelTitleFontColor`…).
- Visual groups: `visualGroup` container + `parentGroupName`; child positions are relative
  to the group; bookmarks toggle `visualContainerGroups[name].isHidden`.
- Filter-pane theme styles (`outspacePane`/`filterCard`) go under
  `visualStyles.page["*"]`. Projection `displayName` renames legend/axis labels.
- Keep every HTML root ≥4px shorter than its visual or a scrollbar appears.
- HTML Content sanitizer: allows `<style>`, `@keyframes`, `@media`, inline SVG; strips
  scripts, `@import`, `@font-face` → system fonts only; the visual cannot navigate pages.
- DAX: a blank compared with `>=`/`<` behaves as 0 → always add `NOT ISBLANK(...)`
  (this bug inflated Funded Within 7 Days % to 42.2%; correct value 37.7%).

## Verified data-quality facts (profiled with pandas, 2026-09-26)

- **MPI file**: 2,772 rows, only 1,008 real (984 with MPI + 24 country-only).
- 87 loan countries; 29 of them have no MPI score (e.g. Chile, United States, Lebanon,
  Turkey, Kosovo) → surfaced via *MPI Coverage %* / "No MPI data", never silently blank.
- Region-level Loans↔MPI join is not viable (~7.6% name matches) → country grain only.
- `loan_theme_ids`: `id` unique; 107,893 ids not in Loans; 6 loans without a theme row;
  14,813 rows with null theme.
- 93% of loans are pre-disbursed (legitimate metric, not an error).
- 2 loans have funded > requested (kept); one loan has negative days_to_fund (excluded).
- All loan timestamps are `+00:00` (zone dropped in Phase 1).
